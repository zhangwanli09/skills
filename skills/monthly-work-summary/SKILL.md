# 月度工作总结生成器

根据用户在 git 仓库里的提交记录，生成两部分内容：**完成情况**（按项目分组列要点）和 **自评总结**（~200 字）。

为什么从 git 提交出发：提交记录是开发者一个月实际产出的最忠实流水。我们的任务不是把提交逐条搬运出来，而是从中**还原出对外可汇报的工作成果**——读者（上级/HR）关心的是"做成了什么、解决了什么"，不是 commit 流水账。

## 工作流程

### 1. 确定要纳入的仓库

**每个 git 仓库 = 一份总结里的一个「项目」。**

- 用户已经给了仓库路径 → 直接用。
- 没给 → 默认用当前所在的 git 仓库，并主动问一句：「还有其他仓库要一起纳入吗？每个仓库会作为一个项目单独成段。」
- 用户可能一次给多个路径，全部纳入。

### 2. 确定作者

只统计用户本人的提交。对**每个仓库**分别读它的身份配置（不同仓库邮箱/用户名可能不同）：

```bash
git -C <repo> config user.name
git -C <repo> config user.email
```

用 name 和 email 一起作为 `--author` 过滤条件（任一匹配即算本人）。如果用户明确说要用别的作者标识，以用户为准。

### 3. 确定时间范围

默认**本自然月**：当月 1 号 00:00 到下月 1 号 00:00（用 `--until` 取下月 1 号比取"当月最后一天"更稳，避免漏掉月末当天的提交）。

识别用户的覆盖说法：「上个月」→ 上一自然月；「6 月 / 5 月」→ 对应自然月；「最近一个月」→ 今天往前 30 天。换算后向用户复述一下区间，避免理解偏差。

### 4. 收集提交

用 `scripts/collect_commits.py` 统一收集，避免每次手写 git 命令、避免漏掉 `--no-merges` 这类细节：

```bash
python3 scripts/collect_commits.py \
  --repos <repo1> <repo2> \
  --since 2026-06-01 --until 2026-07-01
```

路径相对本技能目录根。脚本只用标准库，无需额外安装；`--help` 可查完整用法。

脚本会：对每个仓库自动读取本仓库作者身份、执行 `git log --no-merges`、剥离合并提交、按仓库分组输出干净的 commit subject（JSON）。如需指定作者，加 `--author "<name-or-email>"`。

如果脚本在某环境跑不通，可手动退回到等价命令：
```bash
git -C <repo> log --no-merges --author="<name>" --since=<since> --until=<until> --pretty=format:%s
```

### 5. 把提交归纳成要点

这是最关键的一步。原始提交有几十条、含噪音，要提炼成 **~10 条**对外可读的成果。

- **剥掉前缀**：`feat:` `fix:` `refactor:` `docs:` `chore:` 等是给开发者看的，汇报里没有意义，去掉。
- **合并同主题**：同一功能的多条提交（如某弹窗的若干次修补）合并成一条成果描述，而不是逐条罗列。`docs:`/`refactor:` 这类内部维护通常并入相关功能条目，或整体压成一条「优化代码结构与文档」，不单独占名额。
- **改写成结果导向**：从"改了什么代码"提升到"交付了什么能力/解决了什么问题"。例如多条关于 AI 生成的提交 → 「为考核标准、得分标准等表单项接入 AI 智能生成」。
- **控制粒度**：全部项目合计 **~10 条**（8~12 条都可），每条 **~30 字**左右。多仓库时按各仓库提交量大致按比例分配条目数——提交多的项目多分几条。

### 6. 项目标题

用仓库的友好名：优先取 git remote 仓库名，否则取仓库文件夹名。把英文仓库名转成可读的中文项目名更好（如 `qianmian-applet` → 「千面绩效小程序」）。拿不准时可问用户每个仓库对应的项目叫什么。

### 7. 写自评总结

~200 字，第一人称，职业、克制的口吻。从这一个月的提交里提炼：**主要交付**、**啃下的硬骨头/技术攻关**、**质量与协作意识**（如规范沉淀、细节打磨）、以及一句**展望**。要言之有物、落到具体工作上，避免"我会继续努力"这类空话堆砌。

## 输出格式

严格按下面的模板输出（冒号用中文全角「：」）：

```
完成情况：
<项目A名称>：
1. xxx
2. xxx
3. xxx

<项目B名称>：
1. xxx
2. xxx

自评总结：
xxx（约 200 字）
```

单个项目时也保留「项目名称：」这一行。完成情况各项目编号独立从 1 开始。
